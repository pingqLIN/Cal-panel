## Report Format Findings

DisplayCAL verification reports are self-contained HTML files. The source documentation says verification reports are plain HTML with embedded JavaScript and include both reference and measurement data. The sampled report confirms this layout:

- `<title>` stores the measurement report version and display title.
- `<h2 id="reporttitle">` stores display name, coordinates/resolution, and report timestamp.
- Hidden inputs store normalized metadata:
  - `FF_display`
  - `FF_instrument`
  - `FF_correction_matrix`
  - `FF_profile`
  - `FF_profile_whitepoint`
  - `FF_profile_whitepoint_normalized`
  - `FF_whitepoint`
  - `FF_whitepoint_normalized`
  - `FF_blackpoint`
  - `FF_testchart`
  - `FF_adaption`
  - `FF_datetime`
  - `FF_data_in`
  - `FF_data_ref`
  - `FF_report_version`
- `FF_data_in` and `FF_data_ref` are embedded CGATS/CTI3 blocks. They include `NUMBER_OF_FIELDS`, `BEGIN_DATA_FORMAT`, `NUMBER_OF_SETS`, and patch rows.
- Average/max ΔE and pass/fail views are generated by the embedded JavaScript from those CGATS blocks. The safe extractor should therefore expose raw CGATS plus computed patch counts first; metric computation should be a separate deterministic module.

## Quick Extraction Tool Fields

Implemented scripts:

- `scripts/displaycal_inventory.py`: inventories local DisplayCAL folders.
- `scripts/displaycal_report_parser.py`: extracts DisplayCAL HTML hidden fields and embedded CGATS patch counts.
- `scripts/displaycal_profile_parser.py`: reads ICC/ICM header and tag table metadata.
- `scripts/displaycal_correction_parser.py`: extracts `.ccss/.ccmx` CGATS headers such as display, technology, reference, spectral band count.

## Correction File Usage

- Drive ASUS VZ249HEG1R CAL/UNCAL reports use `i1 DisplayPro, ColorMunki Display & ASUSTek COMPUTER INC VZ249HEG1R (i1 Pro 3).ccmx`.
- Drive Acer SA241Y H CAL/UNCAL reports use `i1 DisplayPro, ColorMunki Display & Acer SA241Y H (i1 Pro 3).ccmx`.
- Drive Built-in Retina Display CAL/UNCAL reports use `SpyderX & Built-in Retina Display (i1 Pro 3).ccmx`.
- Drive archives contain matching `.ccmx` files beside `.icm/.icc`, `.ti1/.ti3`, `.cal`, `.wrz`, `.gam.gz`, logs, and gamut/CLUT plots.
- Local PnP #2 uses `Dell_U2413_25Jul12.ccss`.
- Local `Dell_U2413_25Jul12.ccss` header says:
  - `ORIGINATOR "X-Rite"`
  - `DISPLAY "Dell U2413"`
  - `TECHNOLOGY "LCD GB-R Phosphor IPS"`
  - `REFERENCE "CS1000"`
  - `SPECTRAL_BANDS "351"`
  - `SPECTRAL_START_NM "380.000000"`
  - `SPECTRAL_END_NM "730.000000"`

Interpretation:

- The Drive cases are instrument/display-specific `.ccmx` matrix corrections. That is strong evidence the operator used a spectrometer-derived correction for each monitor and colorimeter pairing.
- The local case uses a `.ccss` spectral correction for Dell U2413 / GB-R Phosphor IPS, which matches the inferred local target display better than a generic LCD mode would.
- DisplayCAL documentation warns that colorimeters need display-specific correction and that matrices made for one instrument/display combination may not transfer cleanly across different units. That matters most for the Drive `.ccmx` cases.

## Cross-Case Correlations

- Naming convention is consistent: display model + timestamp + whitepoint xy + gamma + profile type.
- Most profile packages use `XYZLUT+MTX`, while one Retina archive uses `1xCurve+MTX`; this likely separates high-quality LUT profiling from a simpler matrix/curve workflow.
- CAL/UNCAL pairs share the same display, instrument, and correction file. This makes paired before/after analysis feasible by joining on display model and report timestamp stem.
- The target whitepoint is usually encoded in filenames and hidden fields:
  - ASUS archive target: `0.3132x 0.3326y`, gamma `2.2`.
  - Acer archive target: `0.3127x 0.329y`, gamma `2.2`.
  - Local PnP #2 target: `0.3127x 0.329y`, gamma `2.2`.
- Hardware/correction fit:
  - ASUS VZ249HEG1R: official LED/IPS; report uses model-specific `.ccmx`, likely suitable.
  - Acer SA241Y H: exact Acer Taiwan page says VA/LED; report uses model-specific `.ccmx`, likely suitable for that unit.
  - Built-in Retina: uses SpyderX-specific `.ccmx`; exact Apple panel generation still unknown.
  - Dell U2413: local `.ccss` explicitly names `Dell U2413` and `LCD GB-R Phosphor IPS`, matching the wide-gamut U2413 family.
